DATA · MARKET DATA · LESSON 08

Tick、逐笔成交与盘口

从 K 线进一步进入更细粒度的市场数据， 理解 Tick、逐笔成交、买卖盘以及 Level-1 和 Level-2 行情之间的区别。

行情数据 进阶 约 30 分钟
01

什么是 Tick 数据？

在前面的课程中，我们学习了 K 线。 K 线会把一段时间内产生的大量行情数据， 汇总成 Open、High、Low、Close 等字段。

Tick 数据则更加接近市场实际发生的实时变化。

在不同数据源中，“Tick”的具体定义可能存在差异， 但通常可以把它理解为： 市场行情发生一次更新时形成的一条细粒度行情记录。

K 线：对一段时间进行汇总
Tick：更接近实时行情变化

因此，Tick 通常比分钟线拥有更细的时间粒度。

02

Tick 为什么需要时间戳？

Tick 数据的核心价值之一， 就是记录市场变化发生的时间。

因此，一条 Tick 通常至少需要关联一个时间信息。

symbol
timestamp
price
volume
...

时间精度可能达到秒、毫秒甚至更细， 具体取决于数据源和交易市场。

在处理 Tick 数据时， 不能只关注价格， 还需要考虑时间顺序。

因为市场数据本质上是一个不断随时间变化的序列。

03

Tick 中通常包含哪些信息？

不同数据源提供的 Tick 字段并不完全相同， 但常见信息包括：

  • 股票或证券代码
  • 时间戳
  • 最新成交价格
  • 成交数量或成交量
  • 买卖方向或相关标识
  • 买卖盘价格与数量

需要特别注意： Tick 并没有一个所有数据源都完全一致的标准字段集合。

因此，在构建行情系统时， 应该先理解数据源的具体定义， 再设计统一的数据模型。

04

什么是逐笔成交？

逐笔成交通常是指对市场实际成交事件进行记录。

一笔成交可以理解为：

某个时间
某个价格
成交了某个数量

因此，逐笔成交数据更加关注 “实际成交发生了什么” 。

它和单纯的最新价并不是一回事。 最新价告诉我们当前看到的价格， 而逐笔成交则试图记录具体的成交事件。

05

逐笔成交通常包含哪些字段？

一条逐笔成交记录通常可能包含：

  • 证券代码
  • 成交时间
  • 成交价格
  • 成交数量
  • 成交金额
  • 成交方向或买卖标识
  • 成交序号等市场数据标识

但实际字段会根据交易所、 数据供应商和行情等级而有所不同。

因此，“逐笔成交”描述的是数据粒度和内容类型， 并不意味着所有供应商的数据结构完全相同。

06

Tick 和逐笔成交有什么区别？

这两个概念经常被混在一起， 但严格来说并不一定完全相同。

“逐笔成交”更强调：

一笔实际成交事件

而“Tick”在不同数据源中可能用于描述 最新价更新、成交事件、 行情快照或者其他细粒度行情变化。

所以：

Tick 是一个更宽泛、依赖数据源定义的概念。
逐笔成交更强调实际成交事件。

学习行情数据时， 最重要的不是死记名词， 而是确认数据源到底提供了什么。

07

什么是盘口？

如果逐笔成交关注的是 “已经发生的交易” ， 那么盘口数据关注的则更多是： “当前市场上挂着什么订单”。

盘口通常展示当前市场中的买方和卖方报价以及对应数量。

买方报价 ← 当前等待成交的买入订单
卖方报价 → 当前等待成交的卖出订单

因此，盘口和逐笔成交描述的是市场不同的一面。

08

什么是买盘和卖盘？

买盘通常表示市场中的买入报价及其数量。

卖盘通常表示市场中的卖出报价及其数量。

最常见的两个概念就是：

B

Bid

买方报价。

A

Ask

卖方报价。

在很多行情系统中， Bid 和 Ask 会进一步形成买卖盘口。

09

什么是买一和卖一？

买一和卖一通常代表当前盘口中最接近成交价格的买方和卖方报价。

可以简单理解为：

买一：当前最高买价
卖一：当前最低卖价

两者之间的价格差， 通常称为买卖价差，也就是 Bid-Ask Spread。

当市场报价不断变化时， 买一和卖一也会不断更新。

10

什么是五档盘口？

在股票行情页面中， 经常可以看到买一到买五以及卖一到卖五。

买五
买四
买三
买二
买一
————
卖一
卖二
卖三
卖四
卖五

每一个档位通常包含：

  • 报价价格
  • 对应委托数量

五档盘口因此比只显示买一和卖一 提供了更深一层的报价信息。

11

什么是盘口深度？

盘口深度可以理解为： 在不同价格位置上，有多少买入或卖出报价。

如果只看买一和卖一， 我们看到的是最靠近当前成交区域的一层报价。

如果继续向外观察更多价格档位， 就可以获得更丰富的市场报价深度。

买一 → 买二 → 买三 → 买四 → 买五 → …
卖一 → 卖二 → 卖三 → 卖四 → 卖五 → …

这也是 Level-2 等更高等级行情经常涉及的内容之一。

12

什么是 Level-1 行情？

Level-1，也常写作 L1， 通常可以理解为基础级别的实时行情服务。

具体内容取决于市场和数据供应商， 但通常会包含基础行情信息，例如：

  • 最新价
  • 涨跌
  • 成交量
  • 成交额
  • 基础买卖报价

L1 的核心特点可以理解为： 提供基础市场行情。

13

什么是 Level-2 行情？

Level-2，也常写作 L2， 通常提供比基础行情更丰富的市场微观结构信息。

具体内容同样取决于交易所和数据供应商， 可能包括更深入的盘口、 逐笔成交以及其他市场数据。

因此不能简单理解为：

L1 = 一档
L2 = 五档

实际上，L1 和 L2 是行情服务等级的概念， 具体字段和数据深度需要以对应市场及供应商定义为准。

14

L1 和 L2 有什么区别？

从学习角度，可以先从“数据深度”理解二者。

L1

基础行情

关注当前市场的核心价格和成交信息。

L2

更深行情

提供更丰富的盘口和交易事件等市场数据。

对行情系统而言， L1 和 L2 最终都需要转换成系统能够统一处理的数据结构。

但在实际项目中， 必须根据具体供应商的授权和字段定义进行适配。

15

行情快照和逐笔成交有什么区别？

这是行情系统中另一个非常重要的区别。

行情快照通常描述：

“现在市场是什么状态？”

而逐笔成交描述：

“刚刚发生了什么成交？”

因此，快照更像某一个时间点的市场状态， 逐笔成交则更像不断发生的事件记录。

16

委托、成交和盘口是什么关系？

可以从一个非常简单的过程来理解。

投资者提交委托
↓
进入市场订单簿
↓
与其他订单撮合
↓
发生成交
↓
形成成交数据

盘口更多反映当前尚未完全成交的报价状态， 而逐笔成交则记录已经发生的交易事件。

两者结合起来， 才能更完整地观察市场交易过程。

17

为什么盘口会不断变化？

因为市场中的委托和成交一直在变化。

  • 新的买单进入市场
  • 新的卖单进入市场
  • 已有订单被成交
  • 委托被撤销或修改
  • 市场价格发生变化

因此，盘口不是一张静态表格， 而是一个不断变化的市场状态。

当行情页面不断刷新买一、卖一以及其他档位时， 本质上是在不断更新这个市场状态。

18

什么是市场微观结构？

当我们从 K 线进一步研究 Tick、 逐笔成交和盘口时， 实际上已经开始接触市场微观结构。

市场微观结构关注的是市场交易如何发生， 例如：

  • 买卖报价如何形成
  • 订单如何进入市场
  • 订单如何撮合成交
  • 成交价格如何变化
  • 盘口深度如何变化

K 线主要告诉我们一段时间内价格发生了什么， 而微观结构数据可以进一步观察市场内部发生了什么。

19

Tick 数据可以生成 K 线吗？

在满足数据完整性和时间定义等条件的情况下， 更细粒度的成交数据可以按照时间区间聚合成 K 线。

例如，将某一个 5 分钟区间内的成交数据进行统计：

第一笔有效成交价格 → Open
区间最高成交价格 → High
区间最低成交价格 → Low
最后一笔有效成交价格 → Close

成交量和成交额则可以按照对应规则进行汇总。

因此可以把它理解为：

细粒度成交数据
↓
按时间区间聚合
↓
K 线
20

K 线可以还原成逐笔成交吗？

通常不能。

一根 K 线只保留了一个时间区间的汇总信息：

Open
High
Low
Close
Volume
Amount

它并没有保存这个时间区间内每一笔成交发生的具体顺序。

例如同样一根 K 线， 可能存在很多种完全不同的成交路径， 但最终得到相同的 OHLC。

因此：

细粒度数据 → 可以聚合成 K 线
K 线 → 通常无法恢复原始逐笔成交

这也是为什么 Tick 和逐笔数据的存储价值很高。

21

为什么 Tick 和盘口数据更难处理？

与日线相比， Tick、逐笔成交和盘口数据的数量会大很多。

同一只股票在一个交易日内， 可能产生大量细粒度行情事件。

因此，行情系统需要考虑：

  • 高频数据写入
  • 大量数据存储
  • 时间序列查询
  • 实时数据推送
  • 数据压缩和归档
  • 数据清洗与异常处理

这也是为什么 Tick 数据往往比日线数据 对行情基础设施提出更高要求。

22

Tick 和盘口应该如何进入数据模型？

在统一行情系统中， 不应该把 Tick、逐笔成交和盘口全部混成一种数据。

它们描述的是不同类型的市场信息。

T

Tick

细粒度的行情变化记录。

T

Trade

实际成交事件。

B

Book

当前买卖报价和市场深度。

这种区分对于后面的 Gateway、 Manager 和 API 设计都非常重要。

23

行情 API 如何提供这些数据？

如果一个行情系统同时支持 K 线、 Tick、逐笔成交和盘口， API 最好将不同类型的数据明确区分。

Quote
→ 当前行情快照

Kline
→ 时间周期行情

Tick / Trade
→ 细粒度行情或成交事件

Order Book
→ 买卖盘与市场深度

这样可以避免让一个接口承担所有行情数据类型， 也更方便不同数据源进行适配。

24

Tick 与盘口学习中的常见误区

误区一：认为 Tick 就等于逐笔成交

Tick 的具体含义依赖数据源定义， 逐笔成交则更强调实际成交事件。

误区二：认为五档盘口就是完整订单簿

五档只是展示一定数量的价格档位， 并不等于完整的市场订单簿。

误区三：认为 L2 在所有市场都完全一样

L2 是一种行情服务等级概念， 具体字段和数据内容需要根据市场和供应商定义判断。

误区四：认为 K 线可以还原 Tick

K 线是汇总结果， 原始成交顺序等细节通常已经丢失。

误区五：只关注价格，不关注数据时间

Tick 和逐笔数据高度依赖时间顺序。 如果时间戳处理错误， 数据分析结果也可能出现问题。

25

如何理解不同层级的行情数据？

到目前为止，可以把行情数据理解成不同的观察层级。

01

K 线

从时间区间观察价格和成交统计。

02

Tick

更细粒度地观察行情变化。

03

Trade

观察具体成交事件。

04

Order Book

观察当前买卖报价和市场深度。

它们并不是互相替代的关系， 而是从不同角度描述市场。

26

从原始行情到研究数据

在一个完整的行情系统中， 原始市场数据最终需要经过采集、 标准化和处理，才能被研究系统使用。

交易市场
↓
原始行情
↓
Gateway / 数据适配
↓
统一数据模型
↓
Manager
↓
API
↓
K 线 / Tick / 盘口 / 研究页面

这也是行情数据课程从基础字段逐渐进入 Tick、盘口和数据基础设施的原因。

数据粒度越细， 系统面对的数据量和实时性要求通常也越高。

27

本篇总结

Tick、逐笔成交和盘口， 让我们从 K 线进一步进入市场内部的交易数据。

01

Tick

更细粒度的行情变化数据，具体定义依赖数据源。

02

逐笔成交

记录实际发生的成交事件。

03

盘口

展示当前买卖报价和对应数量。

04

L1 / L2

代表不同层级的行情服务，具体内容取决于市场和供应商。
