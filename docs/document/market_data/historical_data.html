LESSON 05 · MARKET DATA

什么是历史行情？

实时行情告诉我们股票“现在发生了什么”， 而历史行情则告诉我们“过去发生了什么”。 当我们希望查看一只股票过去某一天的价格、 某一段时间的成交量， 或者研究过去数年的价格变化时， 就需要使用历史行情数据。 本篇将从时间维度理解历史行情， 建立交易日期、历史价格、历史成交和时间序列等基础概念， 并进一步理解历史行情应该如何保存和查询。

第二阶段 · 历史行情与 K 线 基础 约 20 分钟 STOCK LAB
01 · WHAT IS HISTORICAL DATA

什么是历史行情？

历史行情， 可以简单理解为已经发生过的股票市场行情数据。

如果实时行情描述的是：

“现在这只股票多少钱？”

那么历史行情描述的就是：

“过去某个时间，这只股票是什么价格、发生了多少成交？”

例如，我们可能希望知道：

  • 某只股票 2025 年 6 月 18 日的收盘价是多少？
  • 过去一个月每天的最高价和最低价是多少？
  • 某一年每天的成交量如何变化？
  • 某个历史区间内累计成交额是多少？
  • 一只股票过去几年价格经历了怎样的变化？

这些问题都属于历史行情数据的应用范围。

简单理解： 实时行情关注“现在”， 历史行情关注“过去”。
02 · REALTIME VS HISTORY

实时行情与历史行情有什么区别？

实时行情和历史行情并不是两套完全无关的数据。 从某种角度看， 实时行情其实是在不断产生新的市场数据， 而这些已经发生的数据经过整理、确认和保存， 就可以成为历史行情的一部分。

可以把它理解成：

实时行情 → 成交发生 → 数据记录 → 历史行情

两者最大的区别在于时间位置。

01

实时行情

关注当前市场正在发生的价格与成交变化。

02

历史行情

关注已经发生并被记录下来的价格与成交数据。

03

共同基础

两者最终都来源于市场中的交易与行情事件。

03 · TIME DIMENSION

为什么历史行情一定要有时间？

历史行情最重要的特征之一，就是它必须具有明确的时间维度。

如果只保存：

价格 = 100.25

那么这条数据几乎没有办法作为历史行情使用。 我们至少需要知道：

  • 这是什么股票？
  • 这个价格发生在什么时候？
  • 这是哪个交易日？
  • 这是开盘价、收盘价还是其他价格？
  • 数据属于哪个时间周期？

因此，一条完整的历史行情记录， 通常至少需要同时包含：

标的 + 时间 + 行情数据

例如：
600519.SH
2026-09-18
收盘价：……

时间不是历史行情的附属信息， 而是历史行情能够成立的基础。

04 · TRADING DATE

什么是交易日期？

在股票历史数据中， 经常会看到一个非常重要的字段： 交易日期（Trading Date）。

它表示这条行情数据对应的市场交易日期。

例如：

symbol：600519.SH
trading_date：2026-09-18
close：……

这里的交易日期并不只是普通的自然日期。 它与交易所的交易日历有关。

如果某一天市场休市， 那么通常不会存在对应的正常日线成交记录。

因此，查询历史行情时， “日期范围”实际上应该理解为：

某个交易日期范围。

05 · HISTORICAL PRICE

什么是历史价格？

历史价格就是过去某个时间点或某个交易周期内形成的价格数据。

最常见的日线行情中， 通常可以看到：

  • 开盘价：该交易周期开始时形成的价格。
  • 最高价：该交易周期内出现的最高价格。
  • 最低价：该交易周期内出现的最低价格。
  • 收盘价：该交易周期结束时形成的价格。

这四个价格经常被称为： OHLC。

它们是后续学习 K 线最重要的基础。 下一篇课程会专门讨论 K 线， 因此这里先建立概念， 不急着深入 K 线形态和分析方法。

06 · HISTORICAL VOLUME

什么是历史成交？

历史行情不只有价格。 与价格同时记录的， 还有市场成交情况。

最常见的成交字段包括：

  • 成交量：一定时间内形成的成交数量。
  • 成交额：一定时间内形成的成交金额。
  • 换手率：成交量相对于流通股本等基础数据计算得到的指标。

例如一条日线数据可能同时包含：

交易日期：2026-09-18
开盘价：……
最高价：……
最低价：……
收盘价：……
成交量：……
成交额：……

这样一条记录就不仅告诉我们价格是多少， 还告诉我们当天发生了多少交易。

07 · DAILY DATA

什么是日线数据？

日线， 是按照一个交易日对行情进行汇总形成的数据。

如果一只股票在一天中发生了大量成交， 我们没有必要在普通日线页面中展示每一笔成交。 可以把当天的市场活动汇总成一条记录。

例如：

2026-09-18

Open：100.00
High：103.50
Low：99.20
Close：102.80
Volume：……
Amount：……

这样，一天的数据就被压缩成一条结构化记录。

日线数据是股票研究中最常见的历史行情形式之一， 也是后续技术分析、量化分析和回测的重要基础。

08 · TIME SERIES

什么是行情时间序列？

当我们把同一只股票多个交易日的历史行情按照时间顺序排列， 就形成了一组非常典型的时间序列数据。

例如：

2026-09-14 → 收盘价……
2026-09-15 → 收盘价……
2026-09-16 → 收盘价……
2026-09-17 → 收盘价……
2026-09-18 → 收盘价……

每一个日期对应一条行情记录， 多条记录按照时间先后连接起来， 就构成了股票价格的历史轨迹。

这就是为什么股票行情数据特别适合使用 时间序列的方式进行组织。

后续我们学习技术指标、趋势分析、 收益率计算以及量化回测时， 本质上都需要在这种时间序列上进行计算。

09 · DATE RANGE

如何查询一段历史行情？

实际使用历史行情时， 很少只查询一个日期。 更常见的是查询一个时间范围。

例如：

查询 2026-01-01 到 2026-06-30 的历史行情。

一个典型的查询条件可以包括：

  • 股票代码。
  • 开始日期。
  • 结束日期。
  • 数据周期。
  • 是否使用复权价格。

最终返回的结果通常是一组按照时间排序的历史记录。

symbol + start_date + end_date + interval

这会成为后续行情 API 设计中非常常见的一种查询模式。
10 · HISTORICAL ORDER

为什么历史行情通常需要按照时间排序？

历史行情本身具有明显的时间先后关系。 因此，在读取历史数据时， 通常需要明确数据的排序方向。

例如：

01

升序

从较早的交易日开始，逐渐排列到最新交易日。

02

降序

从最新交易日开始，逐渐排列到更早的交易日。

03

明确规则

API 和数据模型最好明确规定默认排序方式。

对数据分析来说， 时间顺序尤其重要。 如果数据顺序错误， 收益率、移动平均线、 技术指标甚至回测结果都可能出现问题。

11 · MISSING DATA

历史行情会不会缺数据？

会。 历史行情并不意味着每一个自然日都有一条数据。

最常见的原因包括：

  • 当天不是交易日。
  • 股票处于停牌状态。
  • 数据源本身存在缺失。
  • 某些证券在特定历史阶段尚未上市。
  • 数据清洗或接口转换过程中出现问题。

因此，如果查询：

2026-01-01 ～ 2026-01-31

返回的记录数量并不一定等于 31 条。

不要把自然日数量直接当成行情记录数量。 历史行情应该按照交易日来理解。
12 · SUSPENSION HISTORY

停牌期间的历史行情怎么办？

这是历史数据中特别容易被忽略的问题。

如果一只股票在某段时间处于停牌状态， 那么这段时间可能没有正常的成交价格。

因此，数据系统不能为了让日期连续， 就随意把前一天的收盘价复制到每一个停牌日期。

例如：

09-01：有成交
09-02：有成交
09-03：停牌
09-04：停牌
09-05：复牌

这里的 09-03 和 09-04 不能简单理解为“这两天的收盘价与 09-02 完全相同”。

正确做法应该保留交易状态和数据缺失语义， 让使用数据的人能够知道： 这段时间没有正常交易成交。

13 · HISTORICAL STORAGE

历史行情应该如何保存？

如果我们开始构建自己的行情数据系统， 一个非常自然的问题就是： 这些历史数据应该怎么存？

最基础的思路是： 每一条历史行情记录都对应一个明确的证券和时间。

例如可以抽象成：

symbol
trading_date
open
high
low
close
volume
amount

多条记录组合起来， 就可以形成完整的历史行情表。

在实际系统中， 还可能增加：

  • 数据来源。
  • 数据更新时间。
  • 数据周期。
  • 复权类型。
  • 数据版本或更新时间。
14 · HISTORICAL QUERY

历史行情最常见的查询方式

当历史数据保存下来之后， 最常见的使用方式就是查询。

例如：

01

查询单日

查看某只股票某一个交易日的行情。

02

查询区间

查看开始日期到结束日期之间的完整历史行情。

03

查询最近数据

获取最近若干个交易日的行情记录。

在股票研究系统中， “查询某只股票一段时间的历史行情” 是最基础也最常用的数据请求之一。

15 · HISTORICAL DATA SOURCE

历史行情从哪里来？

历史行情并不是凭空产生的。 它通常来自交易所、券商、专业数据服务商、 金融数据平台或者其他合法的数据接口。

不同数据源在以下方面可能存在差异：

  • 数据覆盖范围不同。
  • 历史数据长度不同。
  • 字段定义可能不同。
  • 更新时间可能不同。
  • 复权数据处理方式可能不同。
  • 数据质量和缺失情况可能不同。

所以在实际构建行情系统时， 不能只考虑“有没有数据”， 还需要考虑数据的来源、定义和质量。

同一个字段名称，不一定意味着所有数据源的定义完全相同。 数据接入时需要进行统一和标准化。
16 · HISTORICAL CONSISTENCY

为什么历史行情需要保持一致性？

历史数据最大的价值之一， 就是可以进行长期比较。

如果同一只股票在不同日期的数据定义完全不同， 那么历史数据就很难用于分析。

例如：

  • 股票代码格式需要尽可能统一。
  • 日期格式需要统一。
  • OHLC 字段定义需要统一。
  • 成交量和成交额单位需要明确。
  • 复权与不复权数据需要明确区分。

这也是为什么专业行情系统通常会设计统一的数据模型， 而不是把不同数据源返回的数据原样混在一起。

17 · DATA AND ANALYSIS

历史行情能用来做什么？

历史行情是股票研究中非常重要的数据基础。 有了历史数据之后， 我们才能对过去的市场表现进行系统分析。

01

趋势研究

观察价格在不同时间阶段中的变化。

02

技术分析

基于历史价格和成交数据计算技术指标。

03

量化研究

使用历史数据进行策略研究、回测和统计分析。

需要注意的是， 历史数据只能告诉我们过去发生了什么。 它本身并不等于未来结果。

数据分析的意义在于帮助我们建立可验证的研究过程， 而不是把历史数据直接当成未来的结论。

18 · HISTORICAL DATA API

历史行情在 API 中应该如何表达？

如果要把历史行情接入一个股票研究系统， 一个常见的 API 思路就是：

股票代码
symbol

开始时间
start_time

结束时间
end_time

数据周期
interval

例如用户可以请求：

某只股票 + 某个日期范围 + 日线数据

系统则返回按照时间排列的一组历史行情记录。

这种接口设计不仅可以用于网页展示， 也可以服务于后续的技术分析、 数据可视化和量化研究。

19 · COMMON MISTAKES

历史行情中的常见误区

学习历史行情时， 以下几个问题尤其值得注意。

01

自然日等于交易日

实际行情数据应该根据交易日历理解，而不是简单按照自然日补齐。

02

没有价格就是数据坏了

停牌、未上市或非交易日都可能导致没有正常行情记录。

03

所有历史价格都一样

不同数据源、复权方式和字段定义可能造成价格数据差异。

20 · HOW TO READ HISTORY

如何阅读一份历史行情？

当你拿到一份股票历史行情数据时， 可以按照下面的顺序进行检查。

  • 第一步：确认股票。 确认 symbol 是否对应正确的证券。
  • 第二步：确认时间。 确认数据对应的交易日期和时间范围。
  • 第三步：确认周期。 判断这是日线、分钟线还是其他周期数据。
  • 第四步：确认价格。 查看开盘、最高、最低和收盘价格。
  • 第五步：确认成交。 查看成交量、成交额等字段。
  • 第六步：确认数据口径。 判断是否复权、单位是什么、数据来自哪里。
先确认数据是什么，再开始分析数据。 这是处理历史行情时非常重要的习惯。
21 · HISTORICAL DATA VALUE

历史行情真正记录的是什么？

从更底层的角度看， 历史行情其实是在记录：

市场在过去某个时间发生过什么。

价格记录了价格变化， 成交量记录了成交数量， 成交额记录了成交规模， 时间记录了这些事件发生的顺序。

当这些数据按照时间组织起来之后， 我们就获得了一个可以被查询、 统计、分析和可视化的市场历史。

所以，历史行情并不仅仅是一张“过去的价格表”。 它实际上是股票市场过去交易活动的一种结构化记录。

22 · LESSON SUMMARY

本篇总结

历史行情是理解股票市场时间维度的基础。 与实时行情相比， 它最大的特点是： 数据已经发生，并按照时间被记录下来。

  • 实时行情主要关注当前市场正在发生的变化。
  • 历史行情记录已经发生的价格和成交。
  • 交易日期是历史行情的重要时间索引。
  • OHLC构成常见历史价格数据的核心。
  • 成交量和成交额描述历史交易活动。
  • 时间序列让多日行情能够按照时间连接起来。
  • 数据口径决定不同历史数据能否被正确比较。

到这里，我们已经完成了从实时行情到历史行情的过渡。 下一步，需要进一步理解： 一天的价格和成交数据究竟是怎样被压缩成一根 K 线的？
